# Feature Specification: 多参考资料电商产品图生成

**Feature Branch**: `dev`

**Created**: 2026-10-31

**Status**: Ready for Technical Planning

**Input**: 运营人员提供分类的包装设计、产品形态图片及自然语言要求，生成一张主要候选产品图。

## Clarifications

### Session 2026-10-31

- Q: 人工审核候选图时，哪些偏差应当使图片不能被接受？ → A: 品牌标识、包装文字及已确认的关键结构必须正确；其他视觉差异由业务人员裁量。
- Q: 首版生成任务是否必须设置费用和耗时的硬性上限？ → A: 不强制硬上限；执行前提供可获得的费用与耗时信息，由运营人员决定是否继续。
- Q: 首版遇到技术故障或图片质量不满意时，应如何处理重试和修订？ → A: 技术故障不自动重试；质量不满意时，由运营人员明确请求修订后再生成。
- Q: 首版应接受哪些格式的参考图片？ → A: 支持 JPEG、PNG；文件大小上限后续确定。
- Q: 首版由谁记录候选图片的最终审核结果？ → A: MCP Server 返回候选图供审核；审核及结果记录由外部业务流程负责。
- Q: 生成任务结果不明且无法查询原任务状态时如何恢复？ → A: 停止自动执行并保留结果不明状态，向调用方说明原任务可能仍在执行以及重复费用或产物风险；不得自动标记失败或取消。运营人员了解风险并给予新的明确授权后可发起新尝试，新尝试须关联原任务且不得覆盖原任务真实状态。上游明确失败时报告失败、不自动重试；结果不明但可查询时优先查询原任务，不重新提交。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 提交两类参考资料并获得候选图 (Priority: P1)

运营人员提交一组包装设计参考图、一组产品形态参考图和自然语言生成要求，获得一张主要候选图并自行裁决是否可用。

**Why this priority**: 这是核心业务结果，包装视觉与产品形态须各有独立来源。

**Independent Test**: 使用各一张有效图片及生成要求完成一次获授权任务，检查候选图及供外部业务流程审核所需的信息。

**Acceptance Scenarios**:

1. **Given** 一至两张有效包装设计图、一至六张有效形态图、每张图的类别说明及自然语言要求，**When** 运营人员授权生成且任务成功，**Then** 系统按两类职责处理资料并返回且仅返回一张主要候选图，供人工裁决。
2. **Given** 任一类别没有有效图片，**When** 运营人员提交任务，**Then** 系统指出缺失类别且不执行生成。
3. **Given** 形态图带有竞品商标或包装图案，**When** 准备目标商品视觉内容，**Then** 这些竞品内容不作为目标品牌视觉来源。

### User Story 2 - 使用多视角与补充说明 (Priority: P1)

运营人员提供包装不同区域设计图和多个产品形态视角，并可用自然语言解释用途或重要性。

**Why this priority**: 多张资料能提供互补信息，避免把不同区域或视角当成同一平面。

**Independent Test**: 分别提供正面、背面设计图与多个形态视角，核对资料分类、说明和可报告的不确定性。

**Acceptance Scenarios**:

1. **Given** 同一包装不同区域的设计图，**When** 处理资料，**Then** 系统保留各资料的区域差异，不默认它们描绘同一平面。
2. **Given** 多个不同视角的形态图与自然语言说明，**When** 处理资料，**Then** 系统综合可用的互补形态信息，并考虑说明中的视角、用途或重要性。
3. **Given** 只有单张形态图且背面不可见，**When** 报告结果，**Then** 不得将缺失的背面结构声称为已真实还原。
4. **Given** 某张图片未说明是包装设计图还是形态参考图，**When** 运营人员提交任务，**Then** 系统要求补充该图片的用途，不执行生成；不强制逐张标记视角。

### User Story 3 - 处理冲突、成本和失败 (Priority: P1)

运营人员需要知道参考资料中的明显冲突或关键结构的不确定性，并掌握执行授权及任务结果。

**Why this priority**: 避免混用包装版本、误报还原结果或重复产生费用。

**Independent Test**: 使用相互矛盾的资料和模拟失败任务，核对反馈、授权和重试行为。

**Acceptance Scenarios**:

1. **Given** 包装设计资料存在明显版本矛盾，**When** 准备生成，**Then** 系统报告冲突，不得擅自混用不同版本。
2. **Given** 形态资料在关键结构上明显矛盾，**When** 处理资料，**Then** 系统暂停并请求运营人员澄清；运营人员明确接受不确定性后，可在标明不确定性后继续生成预览。
3. **Given** 技术故障，**When** 任务失败或结果不明，**Then** 不自动重试；结果不明时先核查原任务状态，不盲目重复提交。
4. **Given** 运营人员对候选图质量不满意，**When** 其明确请求修订，**Then** 可按新的请求及授权生成；不得因质量不满意自动重新生成。
5. **Given** 包装设计存在多个版本，**When** 确定有效版本，**Then** 系统询问运营人员，并以其确认为准，不擅自混用版本。
6. **Given** 系统建议只使用部分参考图以控制成本或耗时，**When** 运营人员尚未确认建议，**Then** 系统不得按该建议筛选执行；经确认后方可使用所确认的集合。
7. **Given** 图片超过已声明的文件大小限制，**When** 运营人员提交任务，**Then** 系统在收费生成前拒绝请求并指出违规图片。
8. **Given** 当前任务与历史任务均有结果，**When** 获取当前任务结果，**Then** 候选图须可追溯至所属任务，不得将历史产物当作当前结果。
9. **Given** 任务成功、明确失败或结果不明，**When** 返回状态，**Then** 系统分别标明对应状态；结果不明时不报告成功或明确失败。
10. **Given** 上游结果不明且无法查询原任务状态，**When** 系统处理该任务，**Then** 停止自动执行、保留结果不明状态，告知调用方任务可能仍在执行及重复费用或产物风险，不自动标记失败或取消，也不未经新授权重新提交。
11. **Given** 上述无法查询的原任务仍结果不明，**When** 运营人员了解风险并明确授权新尝试，**Then** 可发起新尝试并与原任务建立可追溯关联，不覆盖原任务真实状态。

### Edge Cases

- 文件无效、不可访问或类别为空时应识别受影响输入并停止生成。
- 不同参考图的信息量、视角与可信度不同；缺失或不可判定的信息不能当作确定事实。
- 包装不同区域与包装不同版本不可混为一谈；明显版本冲突须报告。
- 包装设计图超过两张或形态参考图超过六张时，系统指出对应类别数量超限且不执行生成；仅接受有效 JPEG、PNG 图片。图片超过已声明大小限制时，须在收费生成前拒绝并指出违规图片。
- 授权不足、上游失败、任务超时或结果不明时，不能报告生成成功或无限重试。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须按包装设计参考资料与产品形态参考资料两个类别接收图片集合；首版包装设计图为一至两张，形态参考图为一至六张，每张均须有效。
- **FR-002**: 系统必须允许每类包含多张图片；不得将输入硬编码为恰好两张或将形态参考限定为单张。
- **FR-003**: 系统必须接收运营人员的自然语言生成要求；运营人员必须逐张说明其用途类别为包装设计图或形态参考图，视角标记为可选，并可补充其他用途或重要性说明。类别缺失时须请求补充，不执行生成。
- **FR-004**: 系统必须区分包装设计的品牌标识、文字、图案、颜色及版式与形态资料的形状、材质及结构职责。
- **FR-005**: 系统必须能处理包装不同区域的设计参考，不默认所有设计图展示同一平面；发现明显版本冲突时报告并询问运营人员确定有效版本，未经业务确认不得混用不同版本。
- **FR-006**: 系统必须能够综合形态参考的互补视角信息，包括可见的形状、厚度、封口、边缘、材质、褶皱与空间比例，不假定各图视角、完整度或可信度一致。
- **FR-007**: 系统必须识别或报告明显的参考资料冲突及无法确定的关键结构信息，不得假定单张形态图完整表达三维结构。
- **FR-008**: 未经业务确认，系统不得将缺失的包装结构信息描述为已真实还原。
- **FR-009**: 系统不得将形态参考图中的竞品商标、品牌名称、文字或图案直接作为目标商品品牌视觉内容。
- **FR-010**: 每次生成任务的输出目标为一张主要候选电商产品图；支持多张输入不扩大输出张数。
- **FR-011**: 成功任务必须返回候选图及供审核的信息；最终审核及结果记录由外部业务流程负责。人工接受图片时，品牌标识、包装文字及已确认的关键结构必须正确；其他视觉差异由业务人员裁量。
- **FR-012**: 生成前必须核对本次任务的业务授权及费用或其他副作用授权；具备技术访问权限不等于获得任务授权。
- **FR-013**: 首版不强制设置费用或耗时硬上限；系统须在执行前提供可获得的费用与耗时信息，由运营人员决定是否继续。上游明确失败时报告失败，不自动重试；质量不满意时，只有运营人员明确请求修订并取得适用授权后才可再次生成。结果不明但可查询时，优先查询原任务状态，不重新提交；无法查询时停止自动执行并保留结果不明状态，向调用方说明原任务可能仍在执行及可能产生重复费用或重复产物的风险。不得未经运营人员新的明确授权重新提交；运营人员了解风险并明确授权后可发起新尝试，该尝试必须与原任务可追溯关联，且不得覆盖原任务真实状态。
- **FR-014**: 系统必须校验每类图片的数量及有效性，数量不在首版范围时指出对应类别并停止生成。首版接受有效 JPEG、PNG 图片，其他格式须指出不支持并停止生成。图片超过已声明的单张文件大小限制时，系统必须在收费生成前拒绝请求并指出违规图片；具体上限在技术选型后结合服务限制与业务需求确定，必要时取得业务确认，且不得超过实际服务或传输能力。传输方式留待技术设计。
- **FR-015**: 形态资料存在明显结构冲突时，系统必须暂停并请求运营人员澄清；运营人员明确接受不确定性后，允许标明不确定性后继续生成预览。
- **FR-016**: 为控制成本或耗时，系统可以建议使用部分参考图，但必须先经运营人员确认所选集合，才能按该集合执行；不得预设自动筛选算法。
- **FR-017**: 生成结果应以已确认的包装设计资料为目标品牌视觉的主要依据，尽可能正确呈现 Logo、包装文字、核心图案、颜色和版式；不得以竞品品牌内容代替目标商品设计。最终接受标准遵循 FR-011。
- **FR-018**: 系统必须建立并提供生成任务与其候选图片产物之间可核对的关联，使当前任务产物能够与历史任务产物区分，不得将历史产物作为当前任务的结果返回。
- **FR-019**: 系统必须区分并报告生成成功、明确失败及结果不明；结果不明不得自动标记为失败或取消，也不得报告为成功。可查询时按 FR-013 优先查询原任务状态，无法查询时保留结果不明并遵循其恢复规则。

### Key Entities *(include if feature involves data)*

- **包装设计参考集合**: 一张或多张图片及其可用的区域、版本和用途说明，提供目标品牌视觉。
- **产品形态参考集合**: 一张或多张图片及其可用的视角、用途和可信度说明，提供包装空间形态与材质线索。
- **生成任务**: 可区分的任务及其两类参考集合、运营要求、业务授权、执行状态、限制及不确定性。
- **主要候选图**: 可追溯到所属任务的一张候选电商产品图及供人工裁决的信息。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在每类各一张及每类多张的有效验收案例中，每个已授权且成功的任务必须返回且仅返回一张主要候选图；有效请求不保证必然成功。
- **SC-002**: 任一类别为空或无有效图片的验收案例中，100% 被指出受影响类别且不执行生成。
- **SC-003**: 对已识别或由运营人员指出的包装版本冲突，系统报告冲突、询问有效版本，未经业务确认不混用不同版本；视觉识别效果由代表性案例和人工审查评估，不承诺识别所有冲突。
- **SC-004**: 对已知单视角未覆盖的关键结构，验收检查不得出现未经业务确认即声称已真实还原的表述；未被识别的信息缺口由人工审核评估。
- **SC-005**: 每个成功任务提供其所属的一张主要候选图及供审核的信息，能够与历史任务产物区分。
- **SC-006**: 在数量边界验收案例中，包装设计图 1、2 张及形态图 1、6 张满足数量条件；包装设计图 0、3 张或形态图 0、7 张均被拒绝并指出对应类别。
- **SC-007**: 100% 的未逐张声明用途类别案例在生成前要求补充；100% 的部分资料选择建议须经运营人员确认后才按建议执行。
- **SC-008**: 在有效 JPEG、PNG 及不支持格式的验收案例中，100% 的不支持格式被指出且不执行生成；有效格式仍须满足其余输入条件。
- **SC-009**: 规格明确外部业务流程负责最终审核及结果记录；MCP Server 将候选图及供审核的信息交付该流程。
- **SC-010**: 人工审核时，接受的图片必须满足已确认品牌标识、包装文字及关键结构正确；其他视觉差异由业务人员最终裁量。
- **SC-011**: 验收案例分别覆盖成功、明确失败、结果不明但可查询及结果不明且无法查询；状态与实际已知结果一致，无法查询时停止自动执行、保留结果不明并报告风险，新授权尝试须关联原任务且不覆盖其真实状态。
- **SC-012**: 对超过已声明文件大小限制的验收图片，收费生成前拒绝请求并指出违规图片。

## Assumptions

- 运营人员有权提供和使用参考资料，并提供目标商品的包装设计；实际权限和业务授权需分别核实。
- 依赖可用的图像生成能力；具体服务、模型、传输和单张图片大小上限尚未选定；须核实实际服务支持 JPEG 和 PNG，上限不得超过服务或传输能力。
- 不包含 3D 建模、CAD、网格生成、三维重建或多张输出；不预设自动筛选方案。
- 仓库中未发现已有功能规格，此前没有可核验的质量、成本、耗时及重试具体阈值；本轮明确审核底线、预算和重试原则，不编造数值。
