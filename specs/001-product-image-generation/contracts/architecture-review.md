审查范围为同机、本地文件输入、单用户 MVP；单进程 Python MCP Server、SQLite 和受限本地文件存储。本文不改变业务规格，不增加 LangGraph、Redis、Celery、PostgreSQL 或分布式服务。下列路径和确认组件是候选设计而非已运行能力。

## 本机 Host 授权信任边界（FR-012，待验证）

- **可信主体与范围**：运营人员控制的 Windows 本机、单用户会话、受控 Host 和同机 stdio Server；不适用于多人共享账号、恶意同账号进程或不受控远程客户端。Host Agent 构造提示词；Server 不调用独立 LLM。
- **Host 职责**：通过实际可用的权限机制展示并核对任务、参考资料、提示词摘要、绘图模型、接口、组别、费用/次数与恢复范围，承载运营人员允许、拒绝和形态组合/包装 Mock 组合审核。当前三种 Host 是否能提供这些能力尚待逐版本联调；普通工具可调用性不证明已核对。
- **Server 职责**：核验任务 revision、输入快照、提示词版本/摘要、阶段、范围与可见确认来源；版本变化使适用确认失效；SQLite 限制本地并发、重放和重复提交，记录可见证据及 `unverified`，不伪造身份凭证，不声称远端恰好一次。`approved=true`、模型自述、API Key 和普通工具调用标识均非业务授权证据。
- **确认频率**：每次可能收费的真实外部请求都须独立明确授权，包括适用的安全重试、模型切换、查询和下载；收费属性不明不得推定免费。范围授权只定义整体任务、模型/接口、费用及尝试上限，不代替逐次请求许可。unknown 不可查询后重新提交仍须新的明确风险授权及适用请求许可，不能绕过安全规则。形态组合图和包装 Mock 组合图的人工审核单独进行，审核本身不自动授权收费。当前真实 Host 和逐次授权交接未验证，生产默认拒绝；已批准的隔离 Scope 证据不构成真实收费验证。
- **剩余风险**：Host 自动批准、预授权或同账号进程绕过交互可能允许未经自然人逐次确认的调用；Server 通常无法独立证明自然人、签发者、范围或防伪。不得把 Host 放行或 `unverified` 直接当成业务授权成立。实际的任务范围核对、拒绝、失效和抗重放须分别对 Codex CLI、Claude Desktop、DeepSeek Harness Desktop 测试；无法落实业务授权核对时停止相应收费提交并报告。
- **既有探测证据**：[Host 许可测试记录](host-permission-probe-2026-11-02.md) 记录早期探测；本项目独立 Server 的后续真实 Host 观察见下表，不能把早期探测等同于业务授权。

**三 Host 验证矩阵**：Codex CLI、Claude Desktop、DeepSeek Harness Desktop（desktop Profile）均须分别以本项目独立 Server 和无收费替身验证真人允许、真人拒绝、自动放行配置、任务/提示词/参考图/费用及重试范围的展示、输入变化后的确认失效、Server 实际可见证据，以及 Agent 能否绕过或重放确认。记录版本、配置和无法测试项。可验证的是实际运行下展示与阻止行为、Server 可见数据和本地绑定/去重；单用户受控机器、Host 配置可信、同账号不存在恶意进程则是运行前提，不是单靠替身能够证明的安全保证。Server 无法独立证明自然人确认的情况须作为剩余风险披露，不能伪装已验证。若实测无法满足宪法授权核对要求，停止该 Host 的相关真实收费提交，报告须人工决定的治理处理，不擅自豁免。

### 宪法符合性及治理

宪法 2.0.0 VI 要求收费核对授权、最小权限和未知状态恢复，不要求固定的 OAuth 或独立身份系统。受控 Host 模式原则上可作为执行环境核对方案，但当前授权通道和责任分配未验证，**不能判定 VI 已通过**；I/V 要求记录未验证证据，IV 要求契约与实现一致。无需先行修改宪法；若未来希望免除实际授权核对或把无条件自动放行视为授权，须提请人工批准宪法 VI 不兼容修改或正式例外，并评估主版本升级至 3.0.0；本次不提出自动降级或擅自修宪。

## 三工具确认闭环

1. `prepare_product_image` 校验两类资料、冻结内容并返回 task/revision/input_digest、待确认项和可得费用/时间；不发收费请求。
2. Host Agent 按阶段构造实际提示词，`prepare_product_image` 保存正文、版本、摘要、冻结图片字节及任务修订，并持久化覆盖阶段、输入顺序及内容、模型、端点、分组、输出和恢复范围的执行快照。T023 先实现最小持久化，T024 在其后扩展阶段提示词及修订；Host 展示和证据能力待验证。
3. Host 向运营人员展示并核对快照、可得费用/unknown 和尝试范围；操作者通过实际可用的受控 Host 机制作适用确认。`submit_product_image` 引用已准备的任务版本、提示词版本及执行摘要，Server 复核参考内容、提示词和执行范围，记录可见来源/状态及持久化提交意图；任何关键内容或范围变化使原确认失效。若 Host 无法落实业务授权核对则停止，不以 `approved=true`、调用标识或模型文本冒充授权；可信交接和 Server 可见证据仍须逐 Host 实测。
4. 形态阶段仅用一至六张形态参考，一次正常绘图生成一张六视图组合图；经人工确认后 Mock 阶段仅用组合原图和一至两张设计图，一次正常绘图生成一张六视图包装 Mock 组合图并交人工审核。两阶段修订均产生关联新版本，保留历史；Host 交接须实测。
5. `get_product_image_task` 查询原任务和交付状态；不自动重新提交未知结果。收费测试另获该次明确授权。

## 三个状态维度与恢复（FR-010、011、013、018、019）

| 维度 | 值及含义 | 证据规则 |
|---|---|---|
| 本地任务 | `draft / awaiting_confirmation / ready / active / closed`；`closed` 只指本地流程结束，不能代表远端失败 | 本地持久记录；是否可提交由有效确认和授权另行决定。 |
| 上游尝试 | `not_submitted / submission_uncertain / accepted / running / succeeded / failed / unknown` | 提交前持久化 `submission_uncertain` 后才发送；仅可靠上游证据可记 accepted/running/succeeded/failed；无证据不得推断；unknown 不映射失败或取消。 |
| 本地交付 | `not_available / pending / delivered / download_failed / save_failed / missing_or_corrupt` | 按形态组合版本或包装 Mock 组合版本记录；上游成功不等于 delivered；图片保存、摘要及关联登记后且读取校验通过才标 delivered，不能据此推断整套完成。 |

提交前原子消费授权与意图只能约束本地并发，不能与远端收费提交组成事务，不承诺 exactly-once 或零重复费用。崩溃后 `submission_uncertain` 及未完成尝试按已有 ID 查询原任务；无 ID 或不可查询则保持 unknown，报告可能仍在执行及重复费用/产物风险。上游明确失败时报告；仅在确认技术故障可安全重试且授权覆盖时，按有限策略创建关联尝试；上游成功下载/保存失败分别保留上游 succeeded 和本地错误，允许在授权访问及适用 URL 条件下恢复**下载**已有结果，不发起新生成。

图片先在产物根内独立临时文件保存并验证 MIME、字节、大小及摘要；发布前登记 pending／预期记录，以不覆盖其他产物的方式发布后再登记 delivered。普通 `os.replace` 会覆盖目标，不能单独证明无覆盖发布。文件系统与 SQLite 之间没有跨系统原子事务；崩溃后根据 Attempt、原始证据、文件和摘要对账。崩溃恢复时：

- 文件存在但数据库未登记：只依据持久化 attempt ID、受控文件名、摘要及上游成功证据核对；证据完备且唯一时可登记，否则隔离并报告人工处理，不能猜测归属或覆盖其他文件。
- 数据库记录 delivered 但文件缺失、不可读或摘要不符：将**交付状态**置为 missing_or_corrupt 并报告，保持上游 succeeded；允许安全重取原结果，绝不自动重生成。
- 下载失败或本地写入/重命名失败：分别报告 download_failed 或 save_failed；不得以任务失败覆盖上游成功。重启扫描只限本项目受控目录，不删除未知文件或用户数据。

### 一致性恢复协议

SQLite 是本地任务、操作和关联的权威记录；上游有证据时决定上游执行状态，本地文件的实际内容及摘要决定可交付性。三者各管自己的事实，任何一方不能单独覆盖其他事实。

1. 创建 attempt 时事务写入本地 task/revision、输入与提示词摘要、唯一 attempt_id、状态及提交意图；持久化后才发 POST。若响应带有效上游 task_id，立即绑定 attempt 并事务提交；收到 ID 前崩溃或超时无法证明提交结果，记录 unknown，不能推断未发送或自动重发。
2. 成功查询时核对上游 task_id 与当前 attempt 一致，先事务记录上游成功证据与 `delivery=pending`；不因 HTTP 200、旧文件或路径存在就标记 delivered。上游失败仅据明确证据标记 failed；冲突或异常响应保留原始脱敏证据，标为待人工核对，不覆盖已确认终态。
3. 对每个阶段组合图的成功响应按已核实的供应商输出契约保存候选：以 attempt_id 和产物标识生成不冲突的受控暂存文件名，下载已有结果、检查格式并计算 SHA-256，事务登记预期相对路径、字节数、摘要与上游成功关联；在同一文件系统以不覆盖已有文件方式发布，随后事务登记交付信息。不得擅自丢弃额外结果或将历史产物当作当前组合版本。实现须验证 Windows 实际文件刷新与原子命名语义，不能假定文件系统与 SQLite 有共同事务或断电持久性。
4. 启动或查询时按受控范围逐 attempt 对账：缺上游 ID 不能查时保持 unknown；有 ID 时只查原任务。上游成功、交付未完成且原结果仍可访问时可安全重取**同一结果**；访问失败报告 download_failed 或 save_failed，不重新生成。文件已存在但登记未完成时只有 attempt、路径、摘要和上游证据全部吻合才可完成登记；否则标为待核对，保留文件。已登记文件缺失、不可读或摘要不符时报告 missing_or_corrupt，保留上游成功状态；不能以历史任务文件替补。
5. 恢复和提交使用 SQLite 事务及条件更新防止并发交错；同一 attempt 一次只允许一个恢复者发布/登记，其他调用读取最新状态或报告冲突。锁失效后重新读取版本与文件，冲突不覆盖、不删除未知文件。写库失败、磁盘满、重启、权限拒绝或上游查询失败均返回具体的阶段及可恢复信息。

| 场景 | 必须报告 | 允许的恢复 | 禁止 |
|---|---|---|---|
| 已发送但未获 ID | upstream unknown、可能继续执行/收费 | 人工核查；新尝试需新业务授权及关联 | 自动重提或标失败/取消 |
| 有 ID，上游进行中或查询失败 | 原 ID、最后有据状态和查询失败/待查询 | 有界只读查询同一 ID | 新 POST 或推断失败 |
| 上游成功，下载或保存失败 | upstream succeeded + delivery download_failed/save_failed | 重取同一结果或人工恢复 | 标上游失败、再生成 |
| 文件完成但数据库未登记 | pending/待核对；有证据则补登记 | 验证 attempt、路径、摘要及上游成功后登记 | 按文件名猜归属或覆盖 |
| DB delivered 但文件缺失、不可读或损坏 | upstream succeeded + missing_or_corrupt | 受控重取原结果、保留故障证据 | 冒充成功、替换历史图片或再生成 |
| 上游、DB 与文件证据冲突 | 分别报告各事实及未核实项 | 保留证据、人工核查；只有可靠结果允许状态更新 | 用任意单方覆盖其他事实 |

## 本地文件安全（FR-001–004、014、018）

输入根与产物根分开，受启动账号和 ACL 限制；规范化路径并防重解析点和并发替换，校验实际 JPEG/PNG、类别与数量。首版不设固定业务文件大小上限；仍需防异常解码、资源不足时安全停止、控制并发/下载及核实供应商限制，具体技术保护、检测方式和参数待选型与测试，不等于无限资源。工程指南相关资源预算条款此前被注释，与本次安全要求的治理关系待维护者审查并提出修订建议；不修改治理文件掩盖差异。对快照及提示词摘要绑定授权并提交前复验，输入或提示词变化使相应授权失效；仅向授权目标发送数据，下载 URL 按受控网络策略检查。

上述早期 Host 探测与后续独立 Server 联调的证据等级不同。三个实际 Host 已完成基础工具调用，详见下表；人机许可范围、可信授权交接与变更失效仍未完整验证。真实供应商测试和外部人工业务验收仍需另行完成。供应商验证矩阵见 [provider-adapters.md](provider-adapters.md)。

## 原任务查询费用边界

可能收费的生产查询必须先核验适用于该查询的独立费用授权；生成费用授权、风险关联生成授权和本地资格不自动授予查询许可。当前没有经过验证的生产查询授权来源或计费协议，生产默认安全拒绝。查询价格未知时能否采用有限次数的风险知情授权及其费用上限表达仍待业务决定，不应视为已批准，也不能将费用缺失当作零。

T043-A2-B1a 的本地请求登记保存查询请求身份、隔离验证的授权消费和 Invocation 意图，不发送查询；测试中的一次调用上限仅用于隔离验证。T043-A2-B1b-1 将 `recovery.recover_once` / `original_query.query_once` 接入该登记和独立授权门禁，仅以隔离假适配器验证单步查询，生产查询不得由此放行。后续仍须验证发送边界的复杂崩溃与撤销竞态、真实 Host 来源及供应商查询和计费协议；SQLite 不能保证远端恰好一次。

T043-A2-B1b-2 为查询意图记录不可变的观察基线，并在受控路径确知适配器尚未调用且授权已撤销或过期时，追加绑定 Request、Invocation 和授权的本地停止证据。该证据不退还授权，也不证明外部远程取消；缺失、冲突或无法验证时保守报告不确定。已记录 `response_received` 但缺少 Observation 时，不以摘要推断完整响应或自动重查。最后一次本地复核与适配器调用之间仍存在跨系统竞态；真实 Host、供应商协议、查询费用及生产恢复均未验证。
