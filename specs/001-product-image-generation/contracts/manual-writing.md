## 用户场景与测试 *(必需)*

### 用户故事 1 — 安装与连接（优先级：P1）

团队成员按照与实际发布版本对应的手册安装服务、配置凭据并接入自己的 Host。

**优先级原因**：可复现安装和连接是使用服务的前提。

**独立测试**：在隔离 Windows 环境按手册安装已验证版本，并使用一种适用的本地 stdio Host 配置完成工具发现；分别记录隔离验证和真实 Host 结果。

**验收场景**：

1. **假如**存在已验证版本，**当**成员按手册安装并合并 Host 配置，**那么**命令和配置使用对应版本的真实入口、目录与参数，并给出预期结果。
2. **假如**尚无已验证版本，**当**成员阅读安装说明，**那么**手册说明阻断，不编造标签、提交或通过结果。
3. **假如**Host 已有其他服务配置，**当**成员接入本服务，**那么**手册指导合并条目并保留既有配置。

### 用户故事 2 — 理解能力并安全使用（优先级：P1）

成员了解工具的实际能力、输入和结果，在知悉费用与限制后发起操作，并定位图片和任务状态。

**独立测试**：依据工具发现、源码和验证记录逐项核对手册中的输入、输出、风险和失败处理。

**验收场景**：

1. **假如**操作可能产生费用或外部副作用，**当**成员阅读步骤，**那么**手册说明触发条件、确认方式、费用已知情况及停止条件。
2. **假如**生成结果不明确，**当**成员排障，**那么**手册指导检查原任务与上游身份，不把超时等同于未执行或建议盲目重复生成。
3. **假如**Host 可接收图片但显示位置不同，**当**成员查看结果，**那么**手册分别说明已观察的显示方式和本地文件备用方式。

### 用户故事 3 — 更新、恢复和维护（优先级：P2）

成员在保留配置和本地数据的前提下，依据经验证的步骤更新或恢复；维护者在项目变动后同步手册。

**独立测试**：检查更新、备份、回滚和维护步骤是否对应实际版本与数据兼容证据；未验证操作明确标记。

**验收场景**：

1. **假如**旧版本代码可能不兼容新数据库，**当**成员准备回滚，**那么**手册区分代码切换与数据恢复，提供已验证方案或标记待验证。
2. **假如**功能、配置或版本发生变化，**当**维护者更新手册，**那么**同步核对受影响的规范、实现与验证范围。

### 边界情况

- 不存在的能力或客户端支持情况标为无、不适用或未验证，不能按其他项目推断。
- 用户专属路径、密钥、动态标识和待发布版本须说明获取或输入方式，不伪装成可原样执行的固定值。
- 已定义但为空或非法的凭据不回退到旧值；读取、解析失败和重复字段按实际配置规则报告。
- 取消或超时不证明上游操作已取消；Host 模型调用与绘图供应商费用分别说明。
- 多个 Host 的版本、连接、调用和图片展示分别验证，不以另一 Host 或替身结果代替。

## 要求 *(必需)*

### 功能要求

- **MW-FR-001**：README 必须提供项目概述、最短安装入口及 MANUAL 链接；MANUAL 面向成员提供完整使用流程。规范、指南和手册职责清晰，详细规则保持单一维护来源。
- **MW-FR-002**：MANUAL 必须覆盖环境准备、初始化、可用性测试、客户端配置、启动与排障、文件与资源清单、功能说明、注意事项、升级回滚和常见问题；不适用项说明原因，章节可按项目需要组合。
- **MW-FR-003**：依据实际仓库、版本、依赖锁、源码、工具发现和证据分别记录项目名、发行包、模块、服务名、入口、安装目录、协议、Host 与凭据名称；不得继承其他项目事实。
- **MW-FR-004**：安装、配置、检查和使用示例必须注明适用版本、Shell、前置条件、执行位置、预期结果和失败处理；静态值使用核实后的真实值，动态输入说明获取或输入方法，不包含真实密钥。
- **MW-FR-005**：默认从本项目实际 GitHub 仓库获取已验证版本；Windows 默认目录为 `D:\MCP\ecommerce-product-image-creator-mcp`。锁定依赖安装和日常启动须与实现一致，不在启动或工具调用时安装、构建或升级依赖。无已验证版本时标明待发布。
- **MW-FR-006**：按实现说明项目根 `.env`、进程环境和 Windows 当前用户环境的优先级与错误处理；保留既有私有配置，不在仓库、示例或日志中写入真实密钥。
- **MW-FR-007**：Host 接入仅提供本地 stdio 方案，按实际适用的 Codex、Claude Desktop 和 DeepSeek Harness Desktop 提供完整可合并条目，保留无关服务，并遵守项目交付指南关于配置片段的要求。
- **MW-FR-008**：分别说明各 Host 版本、发现、调用、确认与图片展示；未验证、失败或不支持的能力不得标为通过。特定客户端及网络库版本的代理问题，仅在适用且有依据时记录版本范围、配置合并和复测状态。
- **MW-FR-009**：依据实现与发现结果说明实际 Tools、Resources、Prompts 和模板，以及输入、结果、错误、费用和适用的格式、尺寸、并发、取消、幂等、重试、恢复限制；不存在或未验证的类别如实标注。
- **MW-FR-010**：区分 Team Mode 与 Strict Mode 的实际行为、生成／查询／下载开关和副作用；不得把 Host 确认等同于可独立验证的人类授权，也不得声称未实现的审批或业务流程已完成。
- **MW-FR-011**：升级和回滚须保留 `.env`、图片、数据库与私有配置，说明兼容性、备份及恢复验证；发布记录关联真实版本、完整提交和适用检查。ZIP 仅在明确需要时作为可选交付。
- **MW-FR-012**：手册变更须核对链接、示例格式、参数、实现与规范；分别记录静态检查、隔离安装、协议、真实 Host 和真实供应商的结果及未覆盖事项。文档工作本身不授权收费请求、Host 改动或发布。
- **MW-FR-013**：采用 spec-kit 时，以 `.specify/memory/constitution.md`、当前功能的 spec、plan、tasks 和相关 contracts 为需求及任务依据；撰写指南见 [撰写指南](../manual-writing-guide.md)，交付细则见 [手册与交付规范](../../../docs/delivering/MANUAL-WRITING-GUIDE.md)。冲突须指出并处理，不能修改需求以掩盖实现缺陷。

### 关键实体

- **成员手册**：与特定版本及使用环境对应的安装、操作和维护说明。
- **版本证据**：版本标识、完整提交、适用 CI、安装及验证范围的可追溯记录。
- **Host 配置**：本地 stdio 条目、环境和客户端版本，不包含真实凭据。
