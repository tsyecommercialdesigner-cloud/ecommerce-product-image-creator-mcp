# 供应商接口适配契约（候选，未实现）

依据用户提供的 [GPT Image 2.5 接口](api-endpoints_gptimage-2.5-series.md)、[Nano Banana 接口](api-endpoints_nano-banana-series.md)及本轮用户确认；不是接口授权调用或本项目实测。来源文件中的历史样例仅证明其所述请求的范围；其中 Nano 的相对 `validation/` 证据当前不在本功能目录。接口可能变更，实施前按模型、端点、分组、账号重新核实。

## 本轮用户确认的默认配置

- 默认模型候选为 `gpt-image-2.5-flare-2k`、`gpt-image-2.5-sunburst-2k`；选用哪一个须在任务准备及授权时明确，不以名称推断价格或生成质量。
- 默认使用用户所称的 flux 异步编辑接口 `POST https://ai.t8star.org/v1/images/edits?async=true`，分组默认为逆向分组；“flux”为用户对该接口的称呼，不是将模型字段改为 `flux`。
- 支持其他端点作为备选，仅在用户显式指定具体端点并完成对应授权时使用；不得在错误、超时或不兼容时自动切换。
- 用户确认异步查询覆盖两个系列的无后缀、`-2k`、`-4k` 版本，适用于 `/v1/images/generations` 和 `/v1/images/edits` 的异步模式。这是本轮用户提供的接口能力，不等同本项目对所有组合的独立实测；查询版本支持不等于将全部版本设为默认生成模型。
- `nano-banana-pro` 按支持多参考图编辑处理；保留资料中历史 451 和缺少多图成功样例的事实，实际编码与边界按组合验证。

## 映射与出站请求

- 网关基址为 `https://ai.t8star.org`；鉴权按供应商文档为 `Authorization: Bearer`，实际空密钥字段命名及供应商账户权限应按部署确认，秘密不得写入请求记录或日志。组别、模型、端点和输出选项在准备阶段展示并与一次性授权绑定；不可自动切换逆向组和官转组。GPT 文档说逆向组只支持 model、prompt、size、image、quality；不得假定 `n`、`response_format` 等其他字段生效。文档 size 描述列出尺寸约束而 Edits schema 列三个枚举，视为待确认矛盾，不自行扩大。
- 经校验的图片按用户确认顺序提供，构造图序清单及自然语言标注 artwork/form、区域/版本、视角与重要性；类别是本系统约束，供应商文档不声明图像级类别字段或保证模型服从。避免泄露本地路径；不以 prompt 声称品牌一致性或冲突识别得到保证。
- GPT Edits 候选为 multipart 文件上传；构造 Content-Type 与 boundary 由所选 HTTP 库生成。`image` / `image[]`、重复字段及 8 张上限须按实际供应商确认，未确认前不得当作已兼容。Nano Generations 的 `image` 数组字符串、支持 URL 或 b64 的声明不证明当前支持模型的编码形式；Nano Edits 示例明确重复 `image`，不能据此推定 GPT 使用相同键。Gemini/Chat 图片载荷与 response schema 须在各支持组合验证，不得跨端点复用推测。
- 提交方法为收费 POST；禁止任何层面自动重试、重定向重放、切模型/端点或自动降级。JSON 用 UTF-8；所有大小、内容类型、类别、文件访问和授权先行校验；单图及总量与供应商、传输和内存限制均以确定后较严条件处理。不得静默缩图或仅使用部分图。

## 异步状态与解析

- 默认使用异步 Edits；本轮用户确认 GPT 两个系列的无后缀、`-2k`、`-4k` 版本在 Generations/Edits 异步模式可查询。原资料示例展示 `POST /v1/images/generations?async=true` 及 `GET /v1/images/tasks/{task_id}`；历史 Flare 文本生成实际响应顶层 `task_id`，OpenAPI 则声明 `code/message/data`，默认 Edits 和各后缀组合尚无本项目独立验证。仅按被确认的响应变体提取非空有效 ID，持久化至当前 attempt；不接受互相矛盾的 ID，不以 HTTP 200 单独推断成功。
- 查询历史 JSON `data.status` 中 `NOT_START` 映射等待、`SUCCESS` 映射上游成功；文档还列 `IN_PROGRESS`（进行中）和 `FAILURE`（失败），这两个状态历史未实测。校验返回 task_id 与当前 attempt 一致。未知状态、响应不全、查询失败或无法确定上游结果一律保留 unknown/待查询，保存可脱敏证据；不得根据进度或 HTTP 200 推定成功/失败。`SUCCESS` 后本地文件保存成功才可返回完整候选；保存失败报告上游成功及本地交付失败，禁止重生成。
- 实际 GPT 样例图片数组为 `data.data.data`，上游结构需按所选模型/分组验证；`b64_json` 空字符串不解码。同步 Images 响应的 `data[]`、Gemini 响应 `candidates[].content.parts[].inlineData` 和 Chat `choices[].message.content` 中 Markdown 图片链接为各自文档样例；分接口解析，不将兼容格式视为同一 schema。多候选、无图、无效格式/大小均明确报告不兼容或交付失败，不静默丢弃或挑第一张冒充满足单图约束。
- 上游 URL 是不可信数据，不把供应商 key 附带到结果 URL；仅在已授权网络策略及确认域名内安全下载，检查协议、每次 DNS 解析/跳转、防止内网与重绑定、超时及压缩/下载/解码预算、MIME/图片有效性，文件原子保存并绑定任务摘要。若下载被拒或失败，保留上游成功/本地交付失败，不自动重新生成；URL 和签名不得写入日志。
- 对未收到 task_id 的超时/断连，不能猜测远端 ID 或重新 POST；保留 unknown、风险告知并要求新授权。已取得有效 task_id 时有界只读查询原任务；GPT 查询覆盖按上述用户确认范围设计，Nano 不自动继承。保留上游原生状态、请求 ID、耗时及可得 usage；实际费用按响应中有效 `cost` 的供应商返回值记录，缺失或无效则为 unknown；币种、单位或计费语义未提供时分别标为 unknown，不推断或宣称已核对账单，同一次任务多次查询不得重复累加。

## 必须完成的受控验证

用无权限 fixtures 和受控替身优先验证选定默认组合的逐字段组装、多图字段差异、UTF-8、两种 ID 响应、响应类型和空 Base64、未知状态/字段、错误和 451、无 ID、重启、授权竞争、下载安全和一图产物映射；其他组合仅在决定支持时单独验证。再经单独明确费用授权，选择供应商确认支持的一个默认模型/接口/组别，逐次核验实际请求、1–2 张和最多 8 张参考图、输出数量、结果保存、状态查询及账单；记录真实失败与未验证项，不自动重试。供应商真实价格、上限和质量未核实之前，不宣称功能可用于生产。
