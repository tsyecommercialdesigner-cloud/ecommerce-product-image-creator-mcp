## 技术故障恢复及备选路由

对可安全重试且授权覆盖的技术故障，每个逻辑生成操作、每个模型与接口组合 `max_attempts=3`，含首次；绘图使用异步 Edits 中 `gpt-image-2.5-sunburst` → `gpt-image-2.5-flare`，两者均耗尽后停止并报告。当前两个模型共用一个已批准接口，单个逻辑操作最多 6 次含首次；实际次数受安全条件、可用组合及授权范围约束。同一逻辑操作的计数跨重启持久化，不得通过更换 attempt ID 重置。每次运营人员明确请求并获得适用授权的人工修订是关联历史的新操作，修订轮数不设上限，其技术故障重试独立计数；不得把自动重试伪装为人工修订。

用户已更正：GPT Image 绘图模型不支持 Chat Completions 和 Gemini Official Format；两个格式不作为绘图备选接口。不得从其他模型或兼容接口名称推断 GPT Image 能力；备选组合无契约证据时停止并明确报告。

自动策略必须提前向用户披露并得到覆盖对应模型、端点、次数及费用的授权；不静默切换组别或突破授权。仅在确认失败可安全重试且不存在未知收费副作用时重试，认证/权限拒绝、安全拒绝、无效输入和未支持组合不得以切换或其他通道绕过。超时、断连或提交结果未知时先查询原任务；不可查询则停止，提示风险，需要新的明确授权才可发起关联尝试。记录绘图尝试、结果、可得供应商费用和耗时；Host 自身 token 不由 Server 准确计量；不可因输出质量不满意自动重新生成。实际可安全重试的错误分类和附加整体限制须根据接口证据和业务决策制定和测试。

默认重试间隔为 5 秒。对于 429，使用供应商返回的有效 `Retry-After`；缺失或无法解析时停止并报告，不擅自使用 5 秒替代。等待只在该次故障可安全恢复、授权仍有效且组合次数未耗尽时执行；429、5xx 或网络超时本身均不能证明远程操作没有执行或没有产生收费副作用。等待期间的重启和并发不能绕过持久化计数与待执行时间。

用户决定将 HTTP 500–599 默认归入技术故障重试范围，后续可根据实测修订；每组合仍最多三次。对于绘图收费 POST，单凭 5xx 不能证明远端没有接受或执行请求：如结果不明，仍须按 FR-013 查询或保留 unknown，不自动重提。已证实未执行或上游明确失败且可安全重试的 5xx 才按默认规则执行。此处是现有规格与宪法对未知副作用的约束，不是供应商已验证的 5xx 行为；须以受控替身与供应商证据验证分类。

用户确认供应商不支持绘图提交幂等键。本项目须对绘图操作实现本地持久化去重：稳定的操作标识与任务、revision 和请求摘要绑定，SQLite 唯一约束及条件更新防止同一操作并发重复发送；同标识不同摘要须拒绝，已记录结果或状态直接返回。受授权的安全重试使用独立关联 attempt 并受次数约束；有意发起新业务任务或对 unknown 获得新授权的尝试使用新操作标识，不能仅按相同图片摘要跨任务去重。远端接收与 SQLite 不能原子提交，因此本地去重不能保证远端恰好一次或避免所有重复收费；结果不明继续按查询、保留状态和新授权规则处理。

**优先级**：本节替代下文旧的“禁止自动重试/自动切换”和“其他端点仅显式指定”通用说法；结果不明时禁止自动重提仍有效。不得启用尚未确认受支持、符合安全边界及用户授权的备选组合。

依据用户提供的 [GPT Image 2.5 接口](api-endpoints_gptimage-2.5-series.md)、[Nano Banana 接口](api-endpoints_nano-banana-series.md)及本轮用户确认；不是接口授权调用或本项目实测。来源文件中的历史样例仅证明其所述请求的范围；其中 Nano 的相对 `validation/` 证据当前不在本功能目录。接口可能变更，实施前按模型、端点、分组、账号重新核实。

## 九图失败分析与适配策略

**观察事实**：同一默认模型和异步 Edits 端点的两张合成 PNG 请求返回一张图片；九张 PNG 请求由客户端发送 9 个 `image[]` multipart 文件字段，图片字节合计 880,472、整个 body 882,507 字节，提交 HTTP 200 并取得 task ID，查询后 `FAILURE`、`start_time=0`、`fail_reason` 为 `images supports at most 16 reference images`。`start_time=0` 的供应商语义未经核实，不能证明模型未执行或没有其他副作用。八张小图成功属于此前另一独立 MCP 的单次观察；两次使用的素材、调用路径等不同，且本次实际分组未被响应独立证实。

用户另行授权的九张 1280 × 960 真实商品 JPEG 照片测试，同模型、端点和 9 个 `image[]` 字段，依然返回相同失败信息；详见[验证记录](provider-sixview-validation-2026-11-02.md#追加测试九张较大真实商品照片)。本次素材、格式和提示词均不同，不能据此确定根因或上游实际解析数量，也不能证明当前两至三张 mock 输入组合可用。

**待证假设，不是根因结论**：

1. 供应商或网关的计数、限制配置或错误信息有误；错误文字中的 16 和客户端发送的 9 不足以确定服务器的实际计数或上限。
2. 文档 Edits schema 的 `image` 与本次使用的重复 `image[]` 有差异；解析、转发或参数适配可能不同，但两张 `image[]` 成功并不能证明九张时服务器如何解析。请求证据记录客户端文件清单及 body 总字节，不包含可供重放的完整原始 multipart；未取得服务端解析明细。
3. 当前分组、账号、后端或异步路径的实际路由与历史成功不同；本次未独立核实组别，也无服务端路由/账号策略证据。
4. 除数量外，形态组合图为 1024 × 1024、约 850 KB，其余为 512 × 512 小图；单图尺寸/内容、组合结构或内部处理可能相关，但不能把这些差异当作已证实原因，也没有证据证明模型将组合图拆成六个输入。
5. **用户提出的可能性**：上游服务或网关瞬时超载，并返回了误导性的参考图数量错误。现有证据既没有负载或限流指标，也无法确认错误消息是否准确，不能确认或排除该假设；同样不能据此认定九张输入或编码无关。
6. **用户提出的可能性**：八张原始参考图均为 512 × 512 的简单合成 PNG，文件大小约 2.9–5.3 KB；形态组合图为 1024 × 1024、850,342 字节。上游可能对小尺寸、低信息量或高度压缩的图片做过滤或特殊处理，但当前没有过滤日志、有效图计数或供应商规则证据，无法确认发生了过滤或其与失败的关系。两张输入请求曾成功并不证明每张图片被模型有效使用；其 usage 的 image token 为 0，含义也未经证实。后续对照应区分像素尺寸、压缩后字节和图片内容，不同时改变多项因素后归因。

**处理与离线验证**：供应商返回的已确定输入不兼容不得按可安全重试的 5xx 技术故障自动重提；保留上游原任务 ID、失败与脱敏响应，向调用方报告。禁止自动换字段、组别、模型、端点或静默丢图。若运营人员确认使用部分资料，明确列出使用和省略的图片、已确认形态版本、预期影响及可得费用；任务级资料仍须满足两类最低要求；形态阶段至少保留一张形态参考，mock 阶段须保留已确认组合图及至少一张设计图，获得适用授权后作为关联新操作，不覆盖旧尝试，也不能声称一定兼容。先用离线 multipart 解析替身检查实际字段次数、名称、MIME、字节和来源映射，并模拟异步 HTTP 200 + FAILURE；供应商口径和任何后续付费对照须分别核实、另获授权，本次不请求供应商。

## 映射与出站请求

- 网关基址为 `https://ai.t8star.org`；鉴权按供应商文档为 `Authorization: Bearer`，实际空密钥字段命名及供应商账户权限应按部署确认，秘密不得写入请求记录或日志。组别、模型、端点和输出选项须与经核对的授权范围绑定；授权是否覆盖多次尝试依 Host 能力和实际范围确定；不可自动切换逆向组和官转组。GPT 文档说逆向组只支持 model、prompt、size、image、quality；不得假定 `n`、`response_format` 等其他字段生效。文档 size 描述列出尺寸约束而 Edits schema 列三个枚举，视为待确认矛盾，不自行扩大。
- 经校验的图片按用户确认顺序提供，构造图序清单及自然语言标注 artwork/form、区域/版本、视角与重要性；类别是本系统约束，供应商文档不声明图像级类别字段或保证模型服从。避免泄露本地路径；不以 prompt 声称品牌一致性或冲突识别得到保证。

## 异步状态与解析

- 默认使用异步 Edits；本轮用户确认 GPT 两个系列的无后缀、`-2k`、`-4k` 版本在 Generations/Edits 异步模式可查询。原资料示例展示 `POST /v1/images/generations?async=true` 及 `GET /v1/images/tasks/{task_id}`；历史 Flare 文本生成实际响应顶层 `task_id`，OpenAPI 则声明 `code/message/data`，默认 Edits 和各后缀组合尚无本项目独立验证。仅按被确认的响应变体提取非空有效 ID，持久化至当前 attempt；不接受互相矛盾的 ID，不以 HTTP 200 单独推断成功。
- 查询历史 JSON `data.status` 中 `NOT_START` 映射等待、`SUCCESS` 映射上游成功；文档还列 `IN_PROGRESS`（进行中）和 `FAILURE`（失败）；本项目直接探测已观察到 `FAILURE`，`IN_PROGRESS` 尚未据此确认。校验返回 task_id 与当前 attempt 一致。未知状态、响应不全、查询失败或无法确定上游结果一律保留 unknown/待查询，保存可脱敏证据；不得根据进度或 HTTP 200 推定成功/失败。`SUCCESS` 后本地文件保存成功才可返回完整候选；保存失败报告上游成功及本地交付失败，禁止重生成。
- 实际 GPT 样例图片数组为 `data.data.data`，上游结构需按所选模型/分组验证；`b64_json` 空字符串不解码。同步 Images 响应的 `data[]`、Gemini 响应 `candidates[].content.parts[].inlineData` 和 Chat `choices[].message.content` 中 Markdown 图片链接为各自文档样例；分接口解析。多候选、无图或无效格式须依据具体操作契约报告或处理，不静默丢弃或挑第一张冒充完整套图。
- 上游 URL 是不可信数据，不把供应商 key 附带到结果 URL；仅在已授权网络策略及确认域名内安全下载，检查协议、每次 DNS 解析/跳转、防止内网与重绑定、超时、MIME/图片有效性，文件原子保存并绑定任务摘要。若下载被拒或失败，保留上游成功/本地交付失败，不自动重新生成；URL 和签名不得写入日志。
- 对未收到 task_id 的超时/断连，不能猜测远端 ID 或重新 POST；保留 unknown、风险告知并要求新授权。已取得有效 task_id 时有界只读查询原任务；GPT 查询覆盖按上述用户确认范围设计，Nano 不自动继承。保留上游原生状态、请求 ID、耗时及可得 usage；实际费用按响应中有效 `cost` 的供应商返回值记录，缺失或无效则为 unknown；用户确认绘图 cost 单位为 ฿，并提供 1 ฿ = ¥1.35 作为人民币参考换算；保留来源，不宣称已核对账单，同一次任务多次查询不得重复累加。
