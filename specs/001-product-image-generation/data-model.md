# 数据与状态模型（候选）

本文件描述设计，不等同于已实现 schema；其中早期实现状态为历史描述，当前无收费离线范围及生产缺口见 [离线开发基线](evidence/mvp-offline-baseline-20261112.md)。用户已选择 Host 许可作为授权承载方向，真实 Host 业务授权交接及逐次收费请求许可仍未完成。业务任务、尝试及上游 ID 不同，均须显式区分。

## 实体

| 实体 | 核心字段和约束 |
|---|---|
| Reference | `ref_id`、类别 `artwork/form`、受限根内文件引用、实际 MIME JPEG/PNG、字节数、内容摘要；可选视角、区域、版本、重要性。每任务 artwork 1–2、form 1–6；不设固定业务文件大小上限；技术资源保护和供应商限制另行验证。 |
| Task | `task_id` 唯一、参考集合及其内容摘要、自然语言要求、确认的包装版本/冲突/不确定性、选择结果和修订版本、创建时间。输入或选择变更生成新 revision 并作废原授权。 |
| Form revision | 每次形态候选是一张含六个固定视图及各视图左上角大写英文字母标识的组合图，由一次图像生成产生；关联唯一版本、attempt、文件摘要、人工反馈与确认状态。字母映射为 F=正视、L=左侧、R=右侧、B=后视、T=俯视、Q=右上 45° 正交，只有明确确认的具体版本可供 mock 使用，修订后重新确认。 |
| Form 输入集合 | 每次生成或修订仅含一至六张形态参考图，不含包装设计图或其他图片；前一候选仅供人工审核及版本追溯，修订意见以文本传递。 |
| Mock 输入集合 | 运营人员明确接受且无需再修订的形态组合图原文件一张，加一至两张已确认包装设计图；单次两至三张。原始形态参考图不随 mock 绘图请求上传；任务中保留来源及版本追溯。 |
| Mock revision | 每个包装 Mock 修订关联 task、已确认形态组合版本及其 Artifact ID/摘要、包装版本、唯一 attempt、单张六视图组合 Artifact 及人工审核状态；修订保留历史，未经审核不得标记批准。旧 ViewRevision 类型保留供历史兼容，新组合版本不依赖单视图资格；当前准备记录保存来源关联，实际生成和产物审核仍待实现。 |
| Prompt revision | `prompt_revision`、task/revision、Host Agent 提供的实际提示词及摘要、阶段、参考集合与授权关联；修改提示词需新版本，绘图授权绑定其摘要。Server 不调用独立 LLM 或计量 Host token。 |
| Execution snapshot | 收费前由已有任务准备模式创建，关联 `task_id/revision`、阶段、参考内容摘要及顺序、`prompt_revision/prompt_digest`、目标组合图、模型、端点、分组、输出及授权恢复范围；规范化 `execution_digest` 供 Host 展示和提交时核对。任一关键内容或授权范围改变后旧确认失效，已明确授权的安全切换只在快照范围内执行。确认来源及能否由 Server 验证仍须逐 Host 实测。 |

| Confirmation / Approval | 分开记录业务选择与收费授权，关联 task/revision/input_digest、版本/子集/不确定性、模型/端点/分组/费用操作和风险确认；来源、主体、有效期及防重放凭证只在 Host 实际提供时记录并验证，不编造。记录证据来源及验证状态；缺少独立验证证据时标为 `unverified` 并说明范围，不把调用标识或模型文本当凭证；此状态不证明授权已通过。具体如何核对业务授权待设计；本地操作标识用事务防止并发重复提交。不得保存令牌明文或秘密。 |
| Form review record | `review_id`、task、形态版本、Artifact ID/摘要、`accept/reject/pending` 决定、来源、记录时间、可选到期时间和证据引用；失效状态与原因独立记录。来源初始为 `unverified`，须经服务端来源验证器核对；确认仅作用于具体产物，不构成收费授权。旧记录不自动补作接受或已验证。 |
| Host review interaction | 当前 Host、待确认 task/revision、对象类型（形态组合或包装 Mock 组合）、对应版本与产物摘要、待确认/确认/拒绝/请求修订状态、证据可见性与来源；暂停/恢复机制和字段按 Host 实测确定。形态或当前 Mock 组合变更后旧确认不得用于新内容。 |
| Attempt | 唯一 `attempt_id`、task_id、可选 previous_attempt_id、授权引用、供应商/模型/端点/分组、配置摘要、上游状态与本地交付状态、上游 ID（可空）、上游原生状态、脱敏请求 ID、时间、失败/未知原因、证据来源。结果不明的新尝试必须有独立新授权和原尝试关联。 |
| Retry policy | 业务授权范围、逻辑操作标识、操作类型、模型与接口、失败分类、计数和切换历史；每个逻辑操作内的每个模型与接口组合 `max_attempts=3`（含首次）。SQLite 持久化计数、attempt 链及切换决定，防止重启、并发或更换 attempt ID 重置；运营人员主动授权的新修订为关联历史的新操作，修订轮数不限，独立计数；未知结果不自动重发。 |

### 跨模型执行候选契约（原设计；当前仅离线实现和验证）

一个 Logical Operation 可关联多个不可变 Execution Candidate。每个候选记录唯一 `candidate_id`、根逻辑操作、task/revision、stage、model/endpoint/group、完整 v2 快照及 execution_digest、prompt revision/digest、按序冻结图片标识及内容摘要、来源与前序 candidate、创建时间、资格／确认与供应商能力状态。每个 Attempt 关联其实际 candidate、前序 Attempt 和独立 Intent；保留原快照、证据和产物。candidate 不等于业务 Revision，也不得通过更换 candidate、operation 或 attempt 标识重置根操作预算。

Sunburst→Flare 只改变经批准的模型／端点候选；业务 Task、Revision、Stage、Prompt 正文及版本、有序冻结图片字节与摘要保持一致。模型属于既有 v2 摘要输入，新候选必须生成不同摘要，不能更改已有 v2 算法或覆盖旧快照。旧 LocalEligibility 不自动适用于新候选；业务决定、形态审核及费用授权重新核对其范围。已验证授权若明确覆盖两个候选及次数／费用，可复用其授权范围证据，但每次执行资格和实际快照仍须独立核对。普通字段不能构成可信授权。

后续实施的最小兼容方案：保留现有 `(task_id,revision)` 准备记录作为原始候选来源，新增按 candidate ID 唯一索引的不可变候选表及 Attempt→candidate 关联；不重写旧数据，不把缺失映射或计数当零。根操作下按 `(root_operation,model,endpoint)` 原子计数，每组合最多 3 次、两组合总计最多 6 次，含首次；资格消费、Attempt／Intent、候选引用及计数在同一写事务核验。该结构和跨进程恢复需另行实现及验证。

现有 Form／Mock Prepare 将 `OperationScope.max_attempts` 固定为 3，且现有提交按根操作总计数检查该值；不能将其解释为已授权跨两组合 6 次。后续须明确并实现候选集合、每组合上限及总授权上限的绑定和 Host 展示；若实际授权只覆盖 3 次，超过该范围必须另行核对，不能仅靠备用模型获得新增费用授权。

**失败分类门禁**：受控未发送证据只证明未跨发送边界，不证明原样重试可恢复。确定性图片格式、参数或授权错误须停止并要求纠正；只有经可信来源核验为临时故障、无未知副作用且授权覆盖时才能进入候选评估。429／5xx 单独不证明未执行；超时、断连、processing 或 unknown 不触发切换，优先查询可靠上游 ID。现有 `local_validation` 尚不细分可恢复性，默认不能据此推断可原样重试。
| Image submission deduplication | 绘图操作的稳定操作标识、task/revision、请求摘要、关联 attempt 和状态；同一标识与不同摘要冲突时拒绝。持久化约束只防止本地重复提交，不提供上游恰好一次保证。 |
| Artifact | 每个已生成产物绑定类型（形态组合或包装 Mock 组合）、attempt_id/task_id、相应形态/Mock 组合版本、受控临时和最终路径、MIME、字节数、内容摘要、登记状态及可得审核信息；关联上游成功证据。不得将旧尝试当成新结果。候选与人工验收结果分开，外部业务系统记录最终裁决。 |
| Measurement | 绘图保存供应商返回的有效 `cost`（฿）和耗时，记录来源与采集时间；Host token 消耗不由 Server 准确计量；缺失为 unknown。同一费用多次查询不重复累加。人民币参考值采用用户提供的 1 ฿ = ¥1.35 并记录换算来源，不能冒充账单或实时汇率。 |

## 状态和证据

准备输入的可选 `purpose` 与其他参考资料元数据一并持久化并纳入输入摘要；旧记录没有该字段时沿用原有摘要规则，避免静默改写历史快照。具体冻结字节的最终提交一致性仍由 T027 独立验证。

状态分为独立的本地任务、上游尝试及本地交付三维，不将上游成功等同交付成功；完整定义、转移条件及冲突恢复以 [架构审查决策](contracts/architecture-review.md) 为准。

- **本地任务**：`draft → awaiting_confirmation → ready → active → closed`，允许按实际条件调整；`ready` 不代表授权已取得，`closed` 不代表上游失败。
- **业务阶段**：形态组合图 → 人工审核及可请求修订 → 确认形态版本 → 包装 Mock 组合图 → 人工审核及可请求修订 → 人工裁决；每次正常生成各一张组合图，修订形成新版本并保留历史。
- **上游尝试**：`not_submitted → submission_uncertain → accepted/running → succeeded/failed/unknown`，可依实际证据跳过 accepted/running；持久化提交意图在网络发送前，重启不得自动重提结果不明的尝试。明确可安全恢复的技术故障可按已有授权和持久化计数创建关联尝试；unknown 原尝试仅凭可靠查询证据更新，风险确认与新授权后可产生独立关联尝试。
- **本地交付**：`not_available / pending / delivered / download_failed / save_failed / missing_or_corrupt`；以受控文件可读、摘要及数据库关联为依据，下载或保存失败不改写上游成功。

## 一致性与故障边界

- 使用 SQLite 事务约束唯一 attempt、revision 与本地操作标识，两个进程并发同一操作最多一个取得提交资格；如果 Host 提供可验证的一次性凭证，再约束其消费。事务提交后服务崩溃也可能实际未发送，宁可 unknown；不证明 Host 身份或远端恰好一次。
- 数据库、外部服务、图片文件不在同一个原子事务：产物先写私有临时文件、校验并持久化，再原子命名及登记；任一崩溃点应可审计地恢复或报告不完整，不把历史文件伪装成当前结果。
- 供应商结果需区分上游成功与本地下载/保存成功；只对已确认的模型/端点组合查询已持久化的原 task_id，状态映射见 [供应商适配契约](contracts/provider-adapters.md)。
- 上游成功、受控文件发布与数据库登记是独立步骤；按 [一致性恢复协议](contracts/architecture-review.md#一致性恢复协议) 逐 attempt 对账，缺失、损坏或冲突不得伪装 delivered，不得自动重新生成。
- 输入可变或任务修订使审批失效；防路径穿越、链接逃逸与读取期间文件替换。实际授权发行/身份、数据库权限、数据保留和并发限制仍待验证或决定。
- 确认过的形态版本改变后，旧 Mock 组合版本保留原始关联及历史状态，不得静默改绑；新版本重新核对及授权。

## 输入修订记录（本地隔离实现，Host 来源待验证）

`input_revision_decision` 记录 decision_id、task_id、source_revision、来源输入与执行摘要、有序来源和目标资料元数据及内容摘要、原因、来源声明、可选证据引用、创建与到期时间、未验证信任状态、失效原因、目标修订与执行摘要。记录中的来源声明和决定标识本身不证明真人确认或收费授权。具体 Host 来源验证及业务工具交接仍须 T051–T054；现有实现未提供生产可信来源。

## 预览依据（无收费离线范围）

`attempt_preview` 将已通过本地来源校验的预览决定与提交意图、Attempt 及 v2 执行摘要关联，保存冲突描述、假设、用途、操作范围、来源声明和有效期快照。记录的 `source_trust=unverified` 不证明真人确认；`structure_verified=false` 不表示结构已被验证。历史记录保留提交时依据，查询时另报当前决定是否失效、过期或被新修订取代；旧记录缺失预览依据时为 unknown。产物通过 Attempt 关联这些信息，不修改历史上游状态或文件完整性结论。
