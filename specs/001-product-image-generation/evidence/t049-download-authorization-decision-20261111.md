# T049 原产物下载许可决策候选

> 历史状态说明：本记录反映 2026-11-11 的离线阶段和当时待决的候选政策，并非现行 Team Mode 或 Strict Mode 的授权结论。当前适用规则以 [MCP 工具契约](../contracts/mcp-tools.md)、[成员手册](../../../MANUAL.md)及现行实现为准。

状态：`pending_policy_decision`。本文件是审查候选，不构成负责人批准、许可签发或生产启用。

正式供应商契约要求已授权网络策略和确认域名；当前没有可核验的生产下载许可发行者、撤销交接、下载收费规则或独立授权证据。已批准生成、查询、Locator、上游成功、允许域名和 Artifact ID 均不自动等于下载许可。生产 `_verify_download_scope` 继续拒绝。

| 方案 | 作用与安全边界 | 数据、重放和费用 | 契约与实施 |
|---|---|---|---|
| A：继续拒绝 | 生产不下载；离线测试可注入隔离验证器 | 不新增生产许可记录；费用保持 unknown，不消费生成或查询授权 | 无需扩权，不能满足真实下载能力 |
| B：独立受限许可候选 | 可信 Host 发行、验证和撤销的单次或有界原产物下载许可；须另核验来源与生产网络 | 建议绑定 Task、Revision、Stage、Root、Operation、Attempt、Candidate、执行摘要、Locator、URL 来源、独立内容摘要、时间、撤销、资源预算、已知／未知费用风险、恢复／重放范围及审计身份；不自动转换为生成 Scope 或释放 Reservation | 需要明确许可签发、消费与撤销契约、持久化迁移和跨系统竞态设计；真实 Host／供应商验证及生产启用仍需单独批准，复杂度高于 A |

如采用 B，应由负责人另行决定未知下载费用是否可批准、风险额度如何表达、相同原产物重复获取的最大范围和撤销生效边界；不得把本建议写成已批准规则。DNS 可取消进程、时间／资源上限、无响应子进程的终止及清理策略也需在生产配置和运维边界下核验。B3 的候选到 T048 暂存、无覆盖发布、登记和崩溃对账可先在隔离可信替身下开发，但不得因此赋予生产权限。
