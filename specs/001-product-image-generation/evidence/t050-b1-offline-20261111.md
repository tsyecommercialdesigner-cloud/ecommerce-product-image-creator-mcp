# T050-B1 MCP SDK 与 stdio 离线验证

日期：2026-11-11。隔离 SQLite、锁定 Python 3.12.14、`mcp==2.3.0`、`mcp-types==2.3.0`；不证明真实 Host、供应商或收费授权。T050 仍未勾选。

正式任务：在 `tests/contract/test_mcp_protocol.py` 使用实际锁定 SDK 验证三个工具输入输出 schema、协议/工具错误、结构化结果、stdio stdout 与 stderr，并保存独立协议证据。

独立进程和实际 SDK Client 完成 initialize、tools/list、prepare、submit 拒绝与 get_task。实际发现三个业务工具和既有非收费 `phase2a_probe`，后者是第四个公开工具，不是本轮新增；是否保留由负责人另行决定。三个业务工具的输出 schema 均为允许附加字段的对象；`stage` 是字符串而非 schema 枚举，具体允许值由业务逻辑拒绝校验。Prepare 为支持恢复路径而未在 schema 层统一声明四个准备字段必填；业务层验证其组合。不能将此描述为严格字段级输出 schema 或已完成 Host 集成。

准备成功返回结构化对象与 JSON 文本；无效阶段、缺少字段、类型错误、空参考、Mock 不可信来源、未知 Task 和无授权提交均返回工具 `isError`。普通 `approved` 参数未使提交放行，隔离 SQLite 没有新增 Attempt。无效协议方法由 SDK 抛出 MCPError。SDK Artifact、首次提交及 unknown 重放采用 `test_artifact_reader.py` 和 `test_submit_mcp_b1.py` 的分层联合证据。

真实行为级 Red：SDK 参数验证错误的文本会回显被拒绝输入；未预期工具异常的 traceback 会在 stderr 包含异常原文。`server.py` 的 SDK 调用边界对 Pydantic 参数验证错误与未预期工具异常分别脱敏，保留业务拒绝和协议错误语义；隔离敏感标记在客户端结果和 stderr 均未出现。该测试不证明所有第三方日志或任意业务错误路径均不含敏感信息。

stdio 原始子进程验证初始化帧、非空 stdout 行均为 JSON-RPC 及 EOF 正常关闭；既有 probe 的日志写入 stderr。隔离子进程内替换异步非收费探针，真实 SDK Client 在进度事件后取消，探针退出且会话仍可发现工具；独立异常退出测试验证进程退出码 17。取消与异常测试仅为协议生命周期证据，不代表真实供应商操作已取消。
