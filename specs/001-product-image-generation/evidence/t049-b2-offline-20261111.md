## 实现与隔离证据

锁定 `httpx2/httpcore2 2.16.0`；B1 未有可验证的公开 IP 钉住路径。本轮使用标准库一次性 `pinned_https.open_pinned`：先在既有地址策略完成检查后以数值 IP 建立 Socket，握手前后比较对端；用原始域名作为 TLS SNI 和证书主机名，`CERT_REQUIRED`；HTTP Host 为原域名，不读取环境代理、不跟随重定向、不使用连接池或自动重试。默认来源验证 `_verify_download_scope` 和 `_resolve` 继续拒绝。Loopback 与测试端口通过私有测试替身显式允许，生产默认拒绝；测试 CA 仅由测试注入，没有安装到系统信任库。

`test_pinned_https.py` 使用本地真实 Socket、TLS、隔离 CA 和 HTTP 响应：检查 SNI、Host、对端固定地址、证书主机名不匹配、不受信 CA、无 Content-Length 的流式字节预算、真实读取与传输总体时限、3xx 不跟随以及两次操作分别握手。地址替身被调用一次，连接使用已选数值 IP；这不是生产 DNS 或公网重绑定实测。原有 `test_download_safety.py` 的 37 项仍为 DNS/peer/HTTP 替身证据，不冒充真实连接。

本轮出现实际行为级 Red：`test_real_socket_total_deadline_closes_without_result` 在 Windows 超时边界被分类成 read timeout；按实际采用的剩余预算修正后最终专项通过。读取器对 TLS 状态行、响应头和内容的每次底层读取设置剩余传输预算；但 `_resolve` 尚未实现，DNS 不纳入此传输计时，真实连接超时未以可控真实网络故障直接验证。连接／peer 检查与 TLS 仍需生产网络及完整策略验证。
